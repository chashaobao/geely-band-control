# 领克米家通知语音

版本 0.1.30，通知桥接来自米家 com.xiaomi.smarthome。只匹配完整通知正文、展开正文或标题中的指令码；冲突、过期或重复通知不触发控制。命名空间与银河 GARAGE_V1 隔离，品牌切换关闭语音及授权。

| 米家手动场景名 / 小爱说法 | 通知内容 | 目标 |
| --- | --- | --- |
| 领克测试 | LYNKCO_V1:TEST | 仅手机显示测试通知回执，无控车 |
| 领克锁车 | LYNKCO_V1:LOCK | fr_unlock / LYNK_UNLOCK，当前方向须为上锁 |
| 领克解锁 | LYNKCO_V1:UNLOCK | fr_unlock / LYNK_UNLOCK，当前方向须为解锁 |
| 领克车窗微开 / 领克通风 | LYNKCO_V1:WINDOW_VENT | fr_window / LYNK_WINDOW，车主明确标记微开，方向为打开 |
| 领克车窗全开 | LYNKCO_V1:WINDOW_OPEN | fr_window / LYNK_WINDOW，车主明确标记全开，方向为打开 |
| 领克关窗 | LYNKCO_V1:WINDOW_CLOSE | fr_window / LYNK_WINDOW，当前方向须为关闭 |
| 领克切换车窗 | LYNKCO_V1:WINDOW_TOGGLE | 点击当前卡片唯一能识别的车窗按钮，开关方向由车主判断 |
| 领克切换车锁 | LYNKCO_V1:LOCK_TOGGLE | 点击当前卡片唯一能识别的车锁按钮，上锁或解锁由车主判断 |

先在米家智能页面新建「手动执行」场景，命名「领克测试」，添加向手机发送通知的动作，将通知内容完整设为 LYNKCO_V1:TEST，保存；在小爱语音控制/场景入口同步并允许语音执行（不同米家版本入口可能不同）。说「小爱同学，领克测试」，先验证伴侣测试回执。然后逐个建立表中场景，通知内容仅放对应指令码，场景名带领克避免与银河重名。米家若未提供手机通知动作或小爱不可发现该场景，应先处理该版本支持问题。

伴侣先选择领克、授予通知使用权并打开米家语音。添加官方卡片后先刷新车况。`WINDOW_TOGGLE` 与 `LOCK_TOGGLE` 可使用自动识别的按钮，无需手动标记方向；识别到多个同类按钮时，应改用穿戴端手动选择。明确的上锁、解锁、微开、全开和关窗指令仍需核对当前按钮的功能和动作方向。图标或描述变化会使旧标记失效。

开启允许车控和米家语音后，从米家收到有效控制通知会由手机直接派发，无需启动穿戴通信。穿戴手动操作仍在穿戴端确认一次，自动识别到的车锁或车窗可直接确认切换。伴侣只在同一卡片于 5 秒内出现与本次动作匹配的新官方弹窗时提交一次确认。未知动作、标题不匹配或过期时，仍交由车主在手机卡片上处理。回执表示指令已转交，最终状态以官方 App 与车辆为准。

ENGINE、HEAT、COOL、SUNROOF、TRUNK、FIND 等只保留关闭路由占位，不接受执行，也不在领克指令码列表中显示。kjck/ccqk 继续保留中性槽位和待验证提示，不能作为这些语音功能的映射证据。

未验证：kjck/ccqk 功能、所有槽位实际方向及副作用、真机图标指纹、condition_txt/time 格式、verify 触发条件、7 选 4 的车型覆盖、真实米家/小爱及穿戴/车辆端到端行为。本轮只有静态代码、离线构建及模拟协议测试。
